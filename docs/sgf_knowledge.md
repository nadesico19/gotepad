# SGF 节点与属性知识整理

本文以 Smart Game Format FF[4] 为基准，主要整理围棋（`GM[1]`）棋谱中节点能够保存的信息、属性的适用范围以及实现时应注意的限制。

## 1. SGF 的基本结构

SGF 文件是一棵或多棵棋谱树组成的集合。每个节点以分号开始，节点中包含若干属性：

```sgf
(;FF[4]GM[1]SZ[19]
  ;B[pd]C[黑棋小目]
  ;W[dd]TR[pd]
  (;B[qp])
  (;B[dc]))
```

基本概念：

- `;` 开始一个节点。
- `B[pd]` 由属性标识符 `B` 和属性值 `pd` 组成。
- 一个属性可以具有多个值，例如 `AB[dd][pp]`。
- 圆括号表示棋谱树，分叉的圆括号表示变化图。
- 属性在同一节点内的排列顺序通常没有语义差异。
- 同一属性标识符不应在一个节点中重复；多个值应放在同一个属性中。

## 2. 属性类别和放置限制

FF[4] 将属性分为 move、setup、root、game-info 和无特殊类型等类别。

必须注意以下限制：

1. move 属性和 setup 属性不能出现在同一个节点中。
2. 一个节点不能同时包含 `B` 和 `W`。
3. root 属性只能出现在棋谱树的根节点。
4. move 属性不建议放在根节点，尽管规范没有完全禁止。
5. 一条从根到叶的路径上只能有一个 game-info 节点。
6. 带有 inherit 属性的属性会持续影响后代节点，直到被重新设置或清除。

## 3. 落子属性

| 属性 | 含义 | 值示例 |
| --- | --- | --- |
| `B` | 黑棋落子 | `B[pd]` |
| `W` | 白棋落子 | `W[dd]` |
| `KO` | 标记该着涉及特殊的劫争处理 | `KO[]` |
| `MN` | 显式指定当前着的手数 | `MN[42]` |

在 FF[4] 中，停一手使用空落子值：

```sgf
;B[]
;W[]
```

旧棋谱有时使用 `tt` 表示 19 路棋盘上的停一手；新实现应优先输出 FF[4] 的空值形式，同时可以在导入时兼容旧表示。

## 4. 局面设置属性

setup 节点直接设置棋盘局面，不代表正常行棋：

| 属性 | 含义 | 示例 |
| --- | --- | --- |
| `AB` | 添加黑子 | `AB[dd][pp]` |
| `AW` | 添加白子 | `AW[dp][pd]` |
| `AE` | 清空交叉点 | `AE[qq]` |
| `PL` | 指定下一方行棋 | `PL[W]` |

常见用途包括让子局、题目初始局面和局部变化图。

错误示例：

```sgf
;B[dd]AB[pp]
```

该节点混合了 move 和 setup 属性，应拆成不同节点或重新设计局面表达。

## 5. 节点注释和局面评价

这些属性描述当前节点或落子后的局面：

| 属性 | 含义 |
| --- | --- |
| `C` | 长文本评论 |
| `N` | 节点名称 |
| `DM` | 两分、局面均衡 |
| `GB` | 黑棋局面较好 |
| `GW` | 白棋局面较好 |
| `HO` | 关键或热点局面 |
| `UC` | 局面不明 |
| `V` | 数值评价 |

`DM`、`GB`、`GW`、`UC` 等属性的值使用 double 类型：`1` 表示普通程度，`2` 表示强调程度。例如：

```sgf
;B[pd]C[黑棋选择小目]N[第1手]GB[1]V[0.35]
```

## 6. 着手评价

这些属性评价的是当前这一步棋，而不是落子后的整体局面：

| 属性 | 含义 |
| --- | --- |
| `BM` | 恶手 |
| `DO` | 疑问手 |
| `IT` | 趣向手、值得关注的着手 |
| `TE` | 妙手、好手 |

例如：

```sgf
;W[qq]BM[2]C[严重失误]
;B[dc]TE[1]C[好手]
```

## 7. 棋盘标记

标记属性用于复盘界面、题目和讲解图：

| 属性 | 含义 | 示例 |
| --- | --- | --- |
| `TR` | 三角形 | `TR[dd][pp]` |
| `SQ` | 方框 | `SQ[dd]` |
| `CR` | 圆圈 | `CR[pd]` |
| `MA` | 叉号 | `MA[qq]` |
| `SL` | 选中点 | `SL[jj]` |
| `LB` | 文字标签 | `LB[dd:A][pp:B]` |
| `AR` | 箭头 | `AR[dd:pp]` |
| `LN` | 连线 | `LN[dd:pp]` |
| `DD` | 淡化交叉点 | `DD[aa:cc]` |
| `VW` | 限制显示区域 | `VW[aa:jj]` |

部分点列表允许使用 `aa:cc` 形式表示一个矩形区域。实现时应根据具体属性的值类型判断它表示“两个端点”还是“压缩点列表”，不能只根据冒号统一解析。

## 8. 用时信息

| 属性 | 含义 |
| --- | --- |
| `BL` | 黑方剩余时间，单位为秒 |
| `WL` | 白方剩余时间，单位为秒 |
| `OB` | 黑方剩余读秒次数或保留次数 |
| `OW` | 白方剩余读秒次数或保留次数 |

例如：

```sgf
;B[pd]BL[3590.5]
;W[dd]WL[3582]OW[4]
```

## 9. 围棋专用的领地标记

| 属性 | 含义 |
| --- | --- |
| `TB` | 黑方领地 |
| `TW` | 白方领地 |

这些属性通常用于终局数目或分析图，并不等价于在相应位置放置棋子。

## 10. 根节点专用属性

root 属性定义整棵棋谱树的全局信息，只能出现在根节点：

| 属性 | 含义 | 常见值 |
| --- | --- | --- |
| `FF` | SGF 文件格式版本 | `FF[4]` |
| `GM` | 游戏类型，围棋为 1 | `GM[1]` |
| `SZ` | 棋盘尺寸 | `SZ[19]` |
| `CA` | 文本字符编码 | `CA[UTF-8]` |
| `AP` | 生成程序及版本 | `AP[Goban:1.0]` |
| `ST` | 变化图显示风格 | `ST[2]` |

推荐的新文件根节点至少输出：

```sgf
;FF[4]GM[1]SZ[19]CA[UTF-8]AP[Goban:版本号]
```

## 11. 棋局信息属性

game-info 属性描述整盘棋，通常放在根节点：

| 类别 | 属性 |
| --- | --- |
| 棋手姓名 | `PB`、`PW` |
| 棋手段位 | `BR`、`WR` |
| 所属队伍 | `BT`、`WT` |
| 贴目、让子 | `KM`、`HA` |
| 规则和结果 | `RU`、`RE` |
| 日期、地点 | `DT`、`PC` |
| 比赛、轮次 | `EV`、`RO` |
| 主时间、读秒规则 | `TM`、`OT` |
| 棋局名称、总评 | `GN`、`GC` |
| 开局名称 | `ON` |
| 记录者、来源、版权 | `US`、`SO`、`CP` |
| 其他注释 | `AN` |

示例：

```sgf
;PB[Black Player]PW[White Player]
 BR[9d]WR[9d]
 KM[6.5]RU[Chinese]
 DT[2026-07-20]RE[B+R]
```

当一棵 SGF 树合并了多盘棋时，game-info 可以出现在分支开始区分不同棋局的节点上。但同一条根到叶路径中不能再出现第二个 game-info 节点。

## 12. 其他显示属性

| 属性 | 含义 |
| --- | --- |
| `FG` | 将节点或后续内容显示为图形 |
| `PM` | 打印时的手数显示方式，具有继承性 |
| `VW` | 查看区域，具有继承性 |

其中 `PM`、`VW` 会影响后代节点，解析器在遍历分支时需要维护继承状态。

## 13. 文本、转义和未知属性

- 属性标识符由大写 ASCII 字母组成。
- `SimpleText` 和 `Text` 类型可以包含非 ASCII 文本，其字符集由根节点的 `CA` 指定。
- 属性值以 `]` 结束，因此值中的 `]` 必须写成 `\]`。
- 反斜杠自身需要按 SGF 的转义规则处理。
- 未识别的属性不应导致整份棋谱无法读取。
- 如果项目需要无损读取再导出，建议保留未知属性的原始标识符和值列表。

自定义属性虽然可以被部分应用使用，但其他程序可能忽略它们。应优先使用 FF[4] 已定义属性；确实需要扩展时，仍应遵守大写属性标识符和值转义规则。

## 14. 节点综合示例

```sgf
;B[pd]
 C[黑棋选择右上小目]
 N[布局研究]
 TE[1]
 BL[3590.5]
 TR[dd]
 LB[qq:A]
 V[0.35]
```

该节点表示：

1. 黑棋落在 `pd`。
2. 节点附带评论和名称。
3. 当前着被评价为好手。
4. 黑方剩余 3590.5 秒。
5. 棋盘上有三角形和文字标签。
6. 分析程序给出了数值评价 0.35。

## 15. 对 Goban 项目数据模型的建议

建议将棋盘核心记录与 SGF 扩展信息分层：

### 核心棋局层

继续由 `GoCore` 和 `GoCoreRecordTreeNode` 保存：

- UID 和父子分支关系；
- 落子颜色与坐标；
- 棋盘重放所需信息。

### SGF 节点扩展层

为每个 UID 关联额外的 SGF 节点数据，例如：

- 评论 `C` 和节点名称 `N`；
- 着手评价及局面评价；
- 用时信息；
- 棋盘图形标记；
- 未识别属性的原始值。

### 棋谱元数据层

独立保存：

- root 属性；
- 对局双方和比赛信息；
- 规则、贴目、结果；
- 应用程序和字符编码信息。

这种分层可以避免棋盘规则算法依赖 SGF 的显示、评论和元数据，同时仍能通过 UID 将 SGF 节点信息准确关联到记录树。
