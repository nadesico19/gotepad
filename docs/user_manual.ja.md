## はじめに

Gotepad を起動した後、空の 碁盤を作成するか、ファイルまたはシステム クリップボードから SGF 棋譜をロードできます。

### 空の碁盤を作成

1. 右上隅の「新規」をクリックするか、「Ctrl+N」を押します。
2. 行 9、11、13、15、または 19 碁盤を選択します。
3. 「作成」をクリックします。

直接作成されたタグには、デフォルトで「新しいノート」という名前が付けられます。同じ名前のタグがある場合、プログラムは名前の後に番号を追加します。

### 画像から碁盤を作成

デスクトップ版では、新しいインターフェイスで碁盤の路数 を選択し、[ローカル画像の選択] をクリックします。 Android版の場合は「写真」または「アルバム」を選択できます。iOS 版では「撮影」を押すか、その右側の「画像」から写真ライブラリまたはファイル内の画像を選択できます。プログラムは、実際の写真、インターネットのスクリーンショット、または本の写真から現在の盤面を識別し、最初に認識および校正インターフェイスを表示します。縦長の写真の場合は、最初に「画像を時計回りに回転」して表示領域を拡大します。 4 つの黄色の制御点をドラッグし、碁盤 の最も外側の 4 つの交点に合わせて、[現在の 4 つの角に従って再識別する] をクリックします。任意の交差点をクリックして、空の点、黒い石、白い石の間を周期的に修正します。中央の赤い点は、プログラムの信頼レベルが低い位置を示しており、検査に重点を置くことが推奨されます。 石マークは、以下の実際の 石の確認を容易にするために、元の画像の端の一部を残します。確認後、識別された 石は 置き石 ノードとして作成され、碁盤 はデフォルトでロックされます。

画像認識結果は、撮影角度、反射、石 テクスチャ、画面のトリミングの影響を受けます。作成前に、四隅、碁盤 チャンネル番号、およびすべての赤い点の位置を確認する必要があります。ディスクが基本的な 囲碁 規則に準拠していない場合、プログラムは作成を拒否し、修正が必要になります。

### SGFを読み込む

新しいインターフェースを開いた後、「ロード」をクリックしてローカルの `.sgf` ファイルを選択します。最初に他のアプリケーションで完全な SGF テキストをコピーしてから、[貼り付け] をクリックして 棋譜を直接作成することもできます。クリップボード経由で作成された 棋譜には関連付けられたソース ファイルがないため、初めて保存するときに選択する必要があります。

正常にロードされた後、碁盤 は最初の分岐の最後の 局面にローミングされ、棋譜 を参照するときに誤って 着手または 一手戻す を避けるためにデフォルトでロックされます。同じ SGF ファイルが現在開いている場合、プログラムはタグを再度作成せず、既存のタグをアクティブにします。iOS のシステムファイル選択画面から同じ元ファイルを再度開いた場合も、既存のタブに切り替わり、そのタブの未保存の変更を保持します。「名前を付けて保存」後は、新しい保存先に基づいてファイルを識別します。

Windows 版は、起動パラメータで `.sgf` ファイルのパスを受け取れます。エクスプローラーで SGF を開くアプリとして Gotepad を選択するか、コマンドラインで SGF のパスを `Gotepad.exe` に渡すと、起動後に棋譜が直接読み込まれます。複数の SGF を一度に渡した場合は、それぞれ別のタブで開きます。Gotepad がすでに起動している状態で別の SGF をダブルクリックするか、SGF のパスを付けて `Gotepad.exe` を呼び出すと、ファイルは最初のウィンドウへ転送されます。同じファイルがすでに開かれている場合は、その既存タブへ切り替わります。SGF のパスを付けずに `Gotepad.exe` を直接起動した場合は独立した新しいウィンドウが開き、棋譜を並べて比較できます。

macOS 版では、Finder で `.sgf` ファイルを右クリックし、「このアプリケーションで開く」から Gotepad を選択すると、棋譜を直接読み込めます。SGF を Gotepad のアプリケーションアイコンにドラッグすることもできます。複数の SGF を一度に開くと、それぞれ別のタブに読み込まれます。Gotepad がすでに起動している場合、システムから開いた棋譜は最初に起動したウィンドウに転送され、タブで開きます。同じファイルがすでに開いている場合は既存のタブに切り替わり、未保存の変更を保持します。棋譜を並べて比較するために独立したウィンドウをもう一つ開くには、macOS の「ターミナル」で `open -n "/Applications/Gotepad.app"` を実行してください。SGF のパスは付けません。Gotepad を「アプリケーション」フォルダ以外に置いている場合は、コマンド内のパスを実際の App のパスに置き換えてください。Finder で同じ Gotepad App を再度ダブルクリックすると、通常は既存のウィンドウがアクティブになるだけです。`open -n` を使うと、新しい独立したウィンドウを起動できます。SGF を開くデフォルトのアプリを Gotepad にするには、ファイルの「情報を見る」で Gotepad を選択し、「すべてを変更」をクリックしてください。

碁盤 タグがある場合は、新しいインターフェースの右上隅にある「✕」をクリックするか、「Esc」を押して閉じて現在の 対局に戻ります。現在 碁盤が存在しない場合、「閉じる」ボタンは表示されないため、碁盤 を作成またはロードする必要があります。

## 画面構成

- 上部には 棋譜タブ バーがあります。ラベルをクリックして 棋譜に切り替え、ラベルの「✕」をクリックして閉じます。最後のタブを閉じると、新しいメモが自動的に作成されます。
- 左側には、碁盤 と 対局の再生バーがあります。
- メッセージおよび確認ダイアログボックスは、現在のウィンドウ幅に応じて自動的に折り返され、操作ボタンが画面からはみ出さないように、幅はウィンドウの 3 分の 2 を超えません。
- 画面には「ヘーゼルウッドとクリーム」の配色を採用しています。深いコーヒー色のパネルにクリーム色の文字を組み合わせ、使用可能なボタンには明るめの暖かい金茶色の枠線を、無効なボタンには暗い茶色の背景と枠線、灰褐色の文字やアイコンを使用します。主要な操作や選択状態はキャラメルゴールドで、削除やクリアなど慎重な確認が必要な操作のボタンは暗い赤色で示します。碁盤のロックなどのチェックボックスは、濃い茶色の塗りつぶしと明るいクリーム色の輪郭を使用し、選択すると枠内にチェックマークを表示するため、木目の背景上でも見分けやすくなっています。メッセージおよび確認ダイアログのボタンは、マウスを重ねたとき、押したとき、キーボードでフォーカスしたときに表示が変わります。色だけでなく、ボタンの文字からも操作内容を確認できます。碁盤と背景は従来の外観を保ち、システムのファイル選択画面は端末標準のスタイルを使用します。
- 碁盤の右側には、ウィンドウの高さに応じて列を自動的に変更する操作ボタンがあります。
- 右上には歯車形の設定ボタンがあり、「新規」「保存」「名前を付けて保存」「エクスポート」「ツール」「マニュアル」「更新」が並びます。「ツール」には使用頻度の低い棋譜処理機能がまとめられています。「マニュアル」を押すと、設定した表示言語に対応する GitHub 上のユーザーマニュアルがブラウザーで開きます。インターネット接続が必要です。
- Notes、棋譜 情報、および KataGo は同じサイド パネル領域を使用しており、そのうちの 1 つを開くと、他のパネルが折りたたまれます。

画面はウィンドウの実際の高さに応じて自動的に拡大縮小されます。基本倍率は高さ 900 ピクセル以下で 1.0 倍、900～2000 ピクセルでは線形に増加し、2000 ピクセル以上で 2.0 倍になります。設定の「UI の拡大縮小」を有効にすると、基本倍率に選択した倍率を掛けます。フォント、ボタン、アイコン、パネル、ダイアログも同時に拡大され、碁盤カメラは使用可能な領域を再計算して盤面全体を表示します。

デスクトップ版は通常のウィンドウの位置、サイズ、最大化状態を「user://window_state.cfg」に記憶し、次回起動時に復元します。モニターを変更したり、デスクトップのレイアウトを変更した後、保存された場所がどの画面の利用可能な領域内にもない場合、ウィンドウは自動的にホーム画面の中央に戻ります。モバイル バージョンと Web バージョンでは、このウィンドウ状態は使用されません。

## 盤面操作

### 着手

- 碁盤ロックされていない場合は、法定交差点上でマウスの左ボタンをクリック 着手できます。
- 利用可能な場所にマウスを置くと、半透明のプレビューが表示されます。
- 白黒切り替えボタン 石または `Ctrl+Q` を使用して次の色を指定します。通常の 着手の後は、デフォルトで白黒交互が復元されます。

「着手確認」を有効にすると、合法な交点を最初にクリックした時点では半透明の未確定の石だけが表示され、棋譜はすぐには変更されません。設定項目の右側で、確認方法を「アイコンで確認」または「もう一度クリック」から選択できます。「アイコンで確認」では、碁盤右側のツールバー上部に緑色の `✓` と赤色の `✕` が一時的に表示され、それぞれ着手の確定とキャンセルに使用します。「もう一度クリック」では、この2つの一時ボタンは表示されず、現在の半透明の石がある交点をもう一度クリックした場合にのみ着手が確定します。どちらの方法でも、確定前に別の合法な交点をクリックすると未確定の石が移動します。碁盤の外の何もない背景部分をクリックするか、マウスを右クリックするとキャンセルできます。人間模倣対局では、未確定の着手をキャンセルすると、保存して終了するための緑色の `✓` が再び使用可能になります。既存の次の着手分岐に入る場合は、これまでどおり確認なしで直接移動します。この機能はデスクトップ版ではデフォルトでオフ、AndroidやiOSなどのモバイル版ではデフォルトでオンになっています。ユーザーが保存した設定は、プラットフォームのデフォルトより優先されます。
・当プログラムは基本的なルールを遵守し、自殺等の違法行為は認めません。

碁盤 は、半透明のグラフィックスで入力できる次のすべての分岐 着手をマークします。現在のプレイ パスの次のハンドは正方形を使用し、他の分岐は円を使用します。マーカーをクリックすると:

- 現在選択されている色が既存の分岐 着手と同じ場合、この分岐が入力されます。
- 現在選択されている色が既存の分岐 着手の反対側にある場合、選択した色の新しい分岐が同じ場所に作成されます。
- ロック中も四角形または円形の分岐マークを押して、その分岐に移動できます。新しい着手は作成されません。KataGo の候補マークと重なる場合は、候補の変化図への移動が優先されます。

### 一手戻す・Undo・Redo

- ロック解除中に右クリックすると、一手戻す操作の確認を求めます。確認後、現在の着手または置き石ノードと、その後のすべての分岐を削除し、一つ前の局面に戻ります。棋譜の途中でも後続記録が削除されるため、見返すだけなら再生操作を使うか、先に碁盤をロックしてください。
- 碁盤がロックされている場合、マウスの右ボタンは 棋譜を変更せずに、前の 局面にローミングするように変わります。
- 一手戻す は 棋譜編集コマンドであり、[元に戻す] と同等ではありません。
- `Ctrl+Z` は直前の取り消し可能な操作を取り消し、`Ctrl+R` はやり直します。一手戻す操作で削除したノードと後続分岐も Undo で復元できます。碁盤ロックは、棋譜編集を含む Undo/Redo を妨げません。
- アイコンにスラッシュが付いている場合は、対応する Undo または Redo が現在実行できないことを意味します。

### 碁盤ロック

碁盤 のロックを確認するか、「Ctrl+E」を押した後、着手 と 一手戻す は禁止されていますが、引き続き許可されています。

- 再生バー、マウス ホイール、矢印キーを使用して 対局を参照します。
- 次の分岐マークをクリックします。
- 石を検索 や分岐 ブラウズなど、直接 着手ではない機能を使用します。
- 棋譜編集の取り消しとやり直しを含む Undo/Redo。

SGF をロードすると、ロック 碁盤がデフォルトで有効になります。

## 再生と棋譜移動

碁盤 の下の再生バーは、線形パス 対局の現在位置を示します。

再生バー左側の「初期配置」と右側の戻る・進む・再生ボタンは、無効になると文字やアイコンの不透明度を下げて表示し、無効状態の背景は描画しません。

- 再生バーをドラッグまたはクリックしてジャンプします。
-再生バー上にマウスを置くと、対応する番号 手数 が表示されます。
- 「<」、「>」をクリックすると、片手で前後に閲覧できます。
- マウスが 碁盤上にあると、スクロール ホイールは上方向に後退し、下方向に前進します。
- キーボードの「←」、「→」はグローバルなシングルステップブラウズキーです。テキスト ボックスまたはリストの編集中にキーがプリエンプトされることはありません。
- 再生ボタンをクリックすると、設定された間隔に従って自動的に再生されます。停止アイコンをもう一度クリックするか、「Esc」を押して停止します。
- 再生中に、ユーザーが再生バー、スクロール ホイール、方向キーなどを使用して進行状況を変更すると、自動再生は停止します。
- 各プラットフォームでは、進む `>` と戻る `<` の大きな四角ボタンも画面右下に表示され、上から順に進む、戻るです。通常の棋譜モードでは棋譜を一手ずつ移動し、ノートの「集中」モードではノートページを切り替えます。再生バー内の従来の小さなボタンも引き続き使用できます。

複数の分岐を持つ 棋譜の場合、再生バーは現在選択されている直線パスのみを表します。これは 棋譜ツリー全体と同等ではありません。

## 分岐操作

### 本線のみ残す

右上の「ツール」から「本線のみ残す」を選ぶと、各階層の最初の分岐をたどる、棋譜の開始から最後の葉ノードまでの経路だけを残し、すべての脇の分岐を削除します。実行前に確認があり、実行後は残した本線の最終局面へ移動します。全体が一つの履歴操作として記録されるため、1 回の Undo で削除したすべての分岐と操作前の局面を復元できます。

### 石を探す

![開始方向 対局から 石を検索 に向かう](../gotepad-gd/assets/ui/find_previous.svg)

![対局 終了方向 石を検索 に向かって](../gotepad-gd/assets/ui/find_next.svg)

1. 進むまたは戻る 石を検索 アイコンをクリックするか、それぞれ `Ctrl+G` または `Ctrl+F` を押します。
2. マウスを目的の交差点または 石に移動して、不透明な虫眼鏡の位置を確認します。
3. 左クリックすると、指定方向にその交点への着手記録を探し、該当する手に移動します。

開始方向への検索には現在の手も含まれます。終了方向へは現在の再生経路をたどり、他の分岐は検索しません。検索対象は着手位置であり、取り石で空点になった変化や置き石の編集は対象になりません。見つからない場合は検索モードを終了してメッセージを表示します。`Esc` または右クリックで取り消せます。

### 次の分岐を調整・削除

![分岐の並べ替え](../gotepad-gd/assets/ui/reorder_branch.svg)

このボタンは、現在の 局面に少なくとも 1 つのサブ分岐がある場合に使用でき、「Ctrl+X」を押して開くこともできます。 着手分岐と 置き石 分岐の両方がリストされます。

- 各行の両側にある「↑」と「↓」を使用して順序を調整し、パネル上部の緑色の「✓」をクリックして結果を書き込みます。
- 分岐の 碁盤サムネールをダブルクリックするか、サムネールの右側にある「Enter」ボタンをクリックして分岐に直接ローミングします。パネルには、新しい 局面の次の分岐が表示されます。エントリー前に確認されていない順序の調整は破棄されます。
- 行の末尾にある赤い「✕」をクリックして確認し、分岐と後続のすべてのノードを削除します。
- コミットされていないシーケンス調整を中止するには、パネル上部の赤い「✕」をクリックするか、「Esc」を押します。

確認された分岐の削除はすぐに実行され、[元に戻す] で元に戻すことができます。並べ替えがその後放棄されるかどうかには影響されません。 「元に戻す」によって復元された分岐は分岐シーケンスの最後に戻り、自動的に元の位置に戻るわけではないことに注意してください。

### 置き石分岐

![置き石 分岐](../gotepad-gd/assets/ui/setup_branch.svg)

次のステップでは、1 つの 着手ボックスで表現できない分岐が 置き石 個ある場合、ツールバーの上部に数量プロンプトのボタンが表示されます。クリックすると、各分岐によって引き起こされた 碁盤の変更を表示し、ターゲット 分岐に入るように選択できます。

### 分岐の可視化

![分岐の視覚化](../gotepad-gd/assets/ui/branch_visualization.svg)

アイコンをクリックするか、「Ctrl+W」を押して、棋譜 ツリー ビューを開きます。ビューには、分岐 キー ノード、メモのあるノード、および各分岐のリーフ ノードが含まれます。大きな 棋譜が初めて生成されると、進行状況が表示されます。生成されたサムネイルは 棋譜と UID によってキャッシュされます。

- スクロール ホイールを使用してビューをズームします。
- デスクトップ版では、マウスの右ボタンを押したままキャンバスをドラッグできます。また、碁盤サムネイルやボタンに当たらない空白領域から左ボタンでドラッグすることもでき、右ドラッグに対応していないタッチパッドでもビューを移動できます。
- タッチ入力に対応するデバイスでは、碁盤のサムネイルやボタンに当たらない空白部分から指一本でドラッグするとキャンバスを移動できます。Android と iOS のタッチデバイスでは、二本指のピンチで拡大・縮小し、二本指のスライドで移動することもできます。拡大・縮小の中心は二本の指の中点です。
- サムネイルを左クリックして 局面を選択します。
- チェック ボックスの左上隅にある緑色の「✓」をクリックするか、選択したサムネイルをダブルクリックして 局面に移動し、ビューを終了します。
- チェックボックスの右上隅にある赤い「✕」をクリックして、局面 とそれ以降のすべての分岐を削除することを確認します。
- 右上隅の「終了」をクリックするか、「Esc」キーを押してビューを閉じます。

第 1 レベルのメモのタイトルがサムネイルの上に表示されます。コメントが存在する場合は、タイトルの後のコメントの最初の行をセミコロンで接続します。タイトルが空の場合は、コメントの最初の行のみが表示されます。コメントの前にはノートブック マーカーが付きます。タイトルは2行まで表示できます。一行の場合は碁盤に近くなります。内容が長すぎる場合は碁盤の幅で切り詰められます。

## 置き石

再生バーの左側にある「プリセット」をクリックするか、「Ctrl+H」を押してプリセットモードに入ります。入力後は、白黒切り替え以外の通常のボタンが一時的に非表示になります。

- 交差点を左クリックして、現在の色を 置き石 に設定します。
- 右クリックで交点の石を消します。右側の消しゴムボタンを選び、消したい交点を押す方法もあります。
- 置き石モードには黒石、白石、消しゴムがあり、押した道具が有効になります。消しゴムが有効な間は金色で表示されます。`Ctrl+Q` でも黒白を切り替えられます。置き石を置いても色は自動で変わりません。
- 緑の `✓` で変更をまとめて確定します。着手ノードまたは空の碁盤の開始点では新しい置き石ノードを作成し、既存の置き石ノードではそのノードを直接編集します。確定した変更は Undo で取り消せます。
- この変更を中止するには、赤い「✕」をクリックするか、「Esc」を押します。

確定後の盤面は、すべての石の連に呼吸点があるなどの基本ルールを満たす必要があります。既存の置き石ノードを編集すると、新しい盤面からすべての後続分岐を再生できるか確認します。競合があれば変更を破棄し、最初の競合ノードの UID を表示します。編集を続ける場合は棋譜をバックアップし、競合する後続分岐を先に整理してください。碁盤ロック中は置き石モードに入れません。

## 変化図

![変化図](../gotepad-gd/assets/ui/variation.svg)

変化図アイコンまたは `Ctrl+T` を押すと、現在の盤面を変化の開始点として一時棋譜にコピーし、元のルールとコミを引き継ぎます。それ以前の着手はコピーされず、開始局面とそれ以降の変化だけを閲覧できます。主棋譜をすぐに変更せずに試し打ちでき、元の碁盤がロックされていても変化図では着手できます。

- 開始時は元の次の手の色を引き継ぎ、以降は黒白交互に打ちます。
- 再生バー、`<`、`>`、キーボードの `←`、`→`、または碁盤や再生バー上のマウスホイールで記録済みの変化を閲覧できます。`←` で戻り、`→` で進みます。ホイールは通常と同じく、上へ回すと戻り、下へ回すと進みます。入力欄やリストにフォーカスがある場合、方向キーはそのコントロールの操作に使われます。
- 変化図では自動再生や、その他の通常の碁盤ツールとショートカット（`Ctrl+Q`、Undo/Redo を含む）は使用できません。
- 途中の局面からも着手できます。記録済みの次の手と同じ位置ならその手へ移動します。別の位置なら、追加の確認ダイアログを表示せずに現在局面の後の記録をすべて削除し、新しい手を打ちます。着手確認が有効な場合、途中で別の手を打つときも、まず半透明の未確定の石を表示します。選択した方法で着手を確定してから後続の記録を置き換えます。未確定の着手を取り消すと、元の記録は残ります。
- 右クリックまたは右側の消しゴム形の「一手戻す」ボタンを押すと、追加の確認ダイアログを表示せずに実行します。末尾では最後の一手を削除し、途中では現在の一手とそれ以降のすべての変化を削除して、一つ前の局面に戻ります。例えば 10 手記録して第 5 手を表示中なら、第 5～10 手を削除して第 4 手へ戻ります。変化の開始点では戻せず、元の棋譜の石も削除しません。
- 着手確認が有効な場合、右クリックはまず未確定の半透明の石を取り消します。その後にもう一度右クリックすると、一手戻します。
- 緑の `✓` は開始時の元の局面から変化全体を主棋譜に保存して終了します。途中を表示していても、その後の記録済みの変化も保存されます。既存の着手と一致する場合は既存分岐へ移動し、異なる場合は新しい分岐を作成します。
- 赤の `✕` または `Esc` は一時的な変化をすべて破棄し、開始前の元の局面に戻ります。終了時は元の碁盤ロックを復元します。破棄した場合は次の手の色も復元し、保存した場合は保存した手順の末尾に移動します。

KataGo の候補から入ると、候補手順を一時棋譜に自動入力し、パスまたは投了で入力を止めます。さらに打ち進めたり、途中で打ち直したり、一手戻す操作をしたりできます。保存すると、残した候補手順と自分で追加した着手の両方を保存します。開始前に開いていた KataGo 解析パネルは一時的に隠れ、終了後に再び開きます。

## 局面ノートと盤面マーク

![メモ](../gotepad-gd/assets/ui/notes.svg)

メモアイコンをクリックするか、「Ctrl+M」を押してメモパネルを開きます。同じ 局面に複数のメモのレイヤーを含めることができます。

- 「+」をクリックして、0 から始まる番号が付いたメモのレイヤーを追加します。
- 途中の番号がずれないよう、最大番号の最後のノート層だけを閉じられます。閉じると内容が削除されますが、Undo で復元できます。
- 注 No. 0 は現在の 着手またはプリセット ノードに保存されます。後続のノートは SGF の独立したノードに保存されます。

各レベルのメモには、ノード タイトル、コメント、盤面マーク および 着手番号 メソッドが含まれます。タイトルやコメントが変更された場合、その横にある緑色の「✓」を使用して承認するか、赤色の「✕」を使用して破棄します。編集中に「Esc」を押すと編集がキャンセルされ、入力フォーカスが解放されます。未確認のコンテンツを含む他のコントロールをクリックすると、プログラムはそれを保持するかどうかを尋ねます。

着手番号の右側の「集中」で棋譜全体のノートをプレビューできます。PPTX と同じ棋譜ツリー順で、同じ局面のノート層は番号順に表示します。現在局面にノートがあれば選択層から、なければ後方の最も近いノートから開始し、後方になければ前方へ移ります。再生バーでノート間を移動し、`<`、`>` でページを送り、再生ボタンで設定間隔の自動送りができます。右下の大きな移動ボタンも使用できます。内容、番号方式、マークは編集できますが、`+` や `✕` でノート層を追加・削除したり、上部タブで直接切り替えたりはできません。ページ移動には再生操作を使ってください。「集中」は「終了」に変わり、押すと通常モードに戻ります。ノートのない棋譜ではプレビューできません。

各プラットフォームでは、ノートのタイトルとコメントの編集欄に「全選択、コピー、切り取り、貼り付け」のタッチボタンが表示されます。テキスト欄にカーソルを置くか一部の文字を選択してから対応するボタンを押すと、システムのクリップボードとテキストをやり取りできます。デスクトップ版では、システムのキーボードショートカットや右クリックメニューも引き続き使用できます。

着手ツリーを作り終えてノートを書き始めるときは、右上の「ツール」から「ノードのノートを生成」を選択します。まず機能の概要が表示され、「生成」を押すと実行し、「キャンセル」を押すとノートを作成せずに戻ります。棋譜全体をたどり、直属の分岐が二つ以上あるノードと、後続の分岐がない葉ノードに、それぞれノートを1ページ作成します。タイトルは `TODO`、コメントと盤面マークは空で、着手番号は既定の方式になります。初期の空の碁盤と初期配置ノードにも同じ条件を適用します。既にノートがあるノードは、ノートが空でもスキップし、重複して作成しません。現在の局面は移動しません。生成したノートは1回の Undo でまとめて取り消し、Redo で復元できます。

棋譜全体のノートを削除するには、右上の「ツール」から「すべてのノートを消去」を選択します。確認後、すべての局面のタイトル、コメント、着手番号の方式、盤面マークを消去します。操作全体が一つの履歴として記録され、1回の Undo で完全に復元できます。

### 盤面マーク

`ABC` の文字マークと図形マークは、同じ位置に共存できます。三角、四角、丸、バツなどの図形マーク同士は排他的で、同じ位置には一種類だけ置けます。別の図形を追加すると、既存の図形が置き換わります。

- `ABC`: A-Z、a-zの順に文字マークを追加します。
- `TR`: 三角マーク。
- `SQ`: ボックスマーク。
- `CR`: 丸マーク。
- `MA`: バツ印。
- 消しゴム：図形マークを消します。

マークモードでは他の画面要素が一時的に隠れますが、棋譜に記録されている次の着手分岐の四角・丸の位置表示は残るため、次の着手位置にマークを付けやすくなります。ノートのプレビューからマークモードに入った場合も表示されます。この位置表示を押すと、分岐へ移動せずにノートのマークを追加・編集します。空の交点または石を左クリックして追加できます。文字マークはクリック順に割り当てられ、既存の文字を再度押すと削除して後続の文字を振り直します。図形は同じ交点に一種類だけ置けます。別の図形を選んで押すと置き換わり、削除には消しゴムを使います。右側の緑の `✓` で確定し、赤の `✕` または `Esc` で破棄します。黒石上は明るい色、白石上や空点は暗い色で表示します。

### 着手番号

番号付け方法は主に PPTX 写植に使用されます。

- **分岐の相対番号付け**: 前のレイアウト オブジェクト ノードの後に 1 から番号を付け直します。
- **分岐の絶対番号付け**: 前のレイアウト オブジェクト ノードから現在の 局面までの 着手のみをマークしますが、番号付けには現在の分岐内の 着手の実際の 手数 が使用されます。
- **グローバル絶対番号付け**: 対局の開始点から開始して、現在のパス内のすべての 着手に実際の 手数 を使用します。
- **番号なし**: エクスポートされた 碁盤には 着手番号 が表示されません。

同じ交差点に複数の 着手がある場合、エクスポートでは最小の番号が最初に表示され、この番号と 碁盤より下の後続の番号との対応が説明されます。

ノート パネルが開いていて、現在の 局面にノートがある場合、現在のノート タブで選択した番号付け方法に従って 碁盤が優先して表示され、設定パネルの通常の 手数 表示オプションが一時的にオーバーライドされます。メモタグを切り替えたり、メモのある他の 局面にローミングしたりすると、同期的に更新されます。現在の 局面にメモがなく、「+」タグのみが表示される場合は、通常の設定が使用されます。ノートパネルを閉じた後も通常の設定に戻ります。

## 棋譜情報

![棋譜info](../gotepad-gd/assets/ui/sgf_info.svg)

棋譜 情報パネルでは、対局 の名前、イベント、ラウンド、日付、場所、白黒の名前、段位、結果、ルール、コミ、置き石数 の番号、時間、カウントダウン、レイアウト名、レコーダー、ソース、著作権、および 対局の一般的な評価、およびその他の一般的に使用される SGF ヘッダー情報を編集できます。ルールの見出しの右側にあるボタンで `Chinese`、`Japanese`、`Korean` を、コミの見出しの右側にあるボタンで `0`、`6.5`、`7.5` をワンクリックで入力できます。入力欄に直接入力することもできます。タイトルバー右側の `∧`、`∨` ボタンを使うと、表示領域の高さの 3 分の 2 ずつ滑らかに上下へスクロールできます。

変更後、パネル上部の緑色の「✓」をクリックしてすべてのフィールドを一度に送信し、赤色の「✕」をクリックして諦めます。編集中のコンテンツがフォーカスを失うと、それを保持するかどうかも尋ねられます。日付、コミ、置き石数 数値、時刻、結果などのフィールドは、インターフェイスのサンプル形式に従う必要があります。そうしないと、保存時に SGF バリデータによって拒否される可能性があります。

## SGF の保存と読み込み

- 「保存」をクリックするか、「Ctrl+S」を押してパスを確認し、現在の 棋譜を保存します。
- 「保存」をクリックするか、「Ctrl+A」を押して新しいファイルを選択します。
- 既存の保存先でも保存確認が表示されます。SGF の保存成功ダイアログはありません。初回保存や「名前を付けて保存」の成功後はタブ名が保存したファイル名に変わります。失敗時はエラーを表示します。
- タグを閉じると、現在タグが閉じられているかどうかのみが確認され、完全な「未保存の変更」ステータスの検出はまだ実装されていません。積極的に貯蓄する習慣を身につけてください。

SGF の読み込み、保存、エクスポート、または KataGo ファイルの選択中に開けるファイル選択画面は 1 つだけで、同じボタンを繰り返し押しても 2 つ目は開きません。Windows では、Gotepad の背後に隠れたネイティブ ファイル選択画面を再クリックだけで確実に前面へ戻すことはできないため、タスクバーまたは `Alt+Tab` で切り替えてください。

Gotepad は、パス番号、正当なファイル、分岐、AB/AW/AE プリセット操作、タイトル、コメント、共通タグ、およびメインのパスワード情報を読み書きします。このプログラムは、フォーマット バージョン、局面 UID、およびノー​​ト番号付け方法を保存するために使用される、`AP[Gotepad:Version]`、`GP`、`XU`、および `XN` などの Gotepad カスタム プロパティも書き込みます。

新規棋譜、およびルールまたはコミが欠けている読み込み棋譜には、`Chinese` ルールとコミ `7.5` が使用されます。読み込み時にルール名を KataGo が認識できない場合、またはコミが 0～100 の範囲で 0.5 刻みになっていない場合は警告を表示し、これらの既定値に置き換えます。小数部が 0.25 または 0.75 のコミについては、「子」と「目」の単位を混同していないか確認するための専用警告も表示します。Gotepad が保持できる SGF ルート拡張プロパティでは、識別子から規格外の文字を削除します。修復後に空になる、または既存プロパティと衝突する異常プロパティは破棄され、読み込み後に警告が表示されます。再保存すると、修復済みの内容が Gotepad 互換形式で書き出されます。

SGF を保存するとき、Gotepad は書き込み失敗や元のファイルの損傷を避けるために保護措置を講じます。重要 棋譜定期的に「名前を付けて保存」を使用して独立したバックアップを作成することをお勧めします。

注:

- テキスト エディタを使用して Gotepad のカスタム プロパティを自由に変更することはお勧めできません。そうしないと、UID の競合やタイプ エラーによりリロードが失敗する可能性があります。
- Gotepad によって生成されていない SGF の場合、プログラムはこれらのカスタム プロパティを盲目的に信頼しませんが、範囲を満たさない値を検証または無視します。
- 違法な 着手はインポートされません。 SGF のパスは 碁盤状態ノードとして管理されませんが、保存時に 棋譜の要求に応じて生成されます。
- 外部 SGF ソフトウェアは、マルチレイヤー ノート番号などの Gotepad のカスタム データを完全には保持していない可能性があります。ソフトウェア間で交換する前に、元のファイルを保持しておくことをお勧めします。

## 更新の確認

ソフトウェアは起動時に、現在のプラットフォームに適用できる新しいバージョンを一度自動確認します。更新が見つかると、画面右端の「ツール」の下にある「更新」ボタンの文字が、選択中のタブタイトルと同じ金色になります。起動時の確認では結果ウィンドウは自動的に開きません。「更新」をクリックすると GitHub に再接続して確認します。確認後のウィンドウには、現在のバージョン、更新可能な最新バージョン、およびその範囲内で最大 5 バージョン分の更新内容が新しい順に表示されます。過去のバージョンに個別の GitHub Release がない場合は、対応する Tag のバージョンコミット説明を使用します。他のプラットフォーム用プレフィックスが付いたリリースは無視されます。現在のバージョンがすでに最新で、対応する GitHub Release が残っている場合は、そのバージョンの更新内容も表示されます。

正式版は `i.j.k` と表示され、正式版への更新だけを受け付けます。テスト版は `test/i.j.k` と表示され、テスト版と正式版の両方に更新できます。共通版と現在のプラットフォーム専用版から基本バージョン番号が最大のものを選び、同じ番号なら正式版を優先するため、テスト版から同じ番号の正式版にも更新できます。下書きのリリースは対象外です。

右上で「GitHub」または「クラウドドライブ」を選択し、「更新」をクリックすると、システムの既定ブラウザーで対応するダウンロードページを開きます。Gotepad は更新確認とページ表示のみを行い、アプリ内で更新をダウンロードまたはインストールしません。GitHub に接続できない場合も結果ウィンドウにエラーが表示され、「クラウドドライブ」へのリンクは利用できます。

## PPTX のエクスポート

右上隅の「エクスポート」をクリックし、「.pptx」を選択して場所を保存します。 B5横テンプレートを使用してエクスポートすると、以下の内容がレイアウトページになります。

- すべて 局面メモ付き。
- 同じ 局面のノートの各レイヤー。
- メモがない場合でも、すべての枝葉ノードを強制的にエクスポートします。

碁盤 は白黒の出版スタイルを使用し、着手番号 で指定されたメモ、連続した文字、および TR/SQ/CR/MA グラフィック マークを描画します。タイトル、コメント、図のタイトル、着手 の繰り返し番号の説明がレイアウト内に書き込まれます。

エクスポートは現在の再生経路だけでなく棋譜ツリー全体をたどります。長いコメントは続きのページに分割し、タイトルに「（续）」を付けます。ノートのフォーカスモードはノート層単位で表示し、エクスポートの続きのページには分割しません。SVG と PNG のどちらも、ページ数、進捗バー、「キャンセル」ボタンを表示します。生成中に「キャンセル」を押すか、`Esc` を押すか、進捗画面を閉じると中止を要求できます。「出力をキャンセル中…」と表示され、実行中の描画などが終わってバックグラウンド処理が終了すると画面が閉じ、再びエクスポートできます。最後の出力先への書き込み中はキャンセルボタンが一時的に無効になるため、完了までお待ちください。エクスポート中はデスクトップのメインウィンドウを閉じる操作も一時的に無効になります。成功ダイアログはスペース、Enter、`Esc` で閉じられます。

設定の「碁盤 座標のエクスポート（左辺と上辺）」で、エクスポートする 碁盤に座標を含めるかどうかを制御できます。有効にすると、碁盤 の上側に列文字のみが描画され、左側に行番号が描画されます。座標は 碁盤に近く、占有される追加スペースを最小限に抑えるためにエッジ 石を避けます。このオプションはデフォルトではオフになっており、SVG と PNG の両方のエクスポートに適用されます。

### SVG または PNG

「設定 → PPTX 碁盤画像」で形式を選択します。

|フォーマット |利点 |メモ |
|---|---|---|
| SVG (デフォルト) |ベクターは鮮明で、最高の拡大率と印刷品質を備え、一般にファイル サイズが小さくなります。一部の古いバージョンの PowerPoint、WPS、または互換性のあるソフトウェアでは、埋め込まれた SVG が表示されない場合があります。
| PNG |より多くのプレゼンテーションソフトで安定して表示できる | 碁盤は 1600×1600 ピクセルで生成され、ファイルは通常より大きく、極端な拡大は SVG ほど鮮明ではありません。

エクスポートされたファイルが主に新しいバージョンの PowerPoint で使用される場合、または高品質の印刷に使用される場合は、SVG を優先します。不明な環境のユーザーに送信する必要がある場合、または 碁盤画像が表示されないという問題が発生した場合は、PNG を選択します。

### フォント

PPTX の 碁盤番号は PNG モードでラスタライズされていますが、タイトルとコメントは引き続き編集可能なテキストです。現在エクスポートされたファイルにはフォントが埋め込まれていないため、プロジェクトに含まれる Noto Sans CJK SC および Noto Serif CJK SC フォントを編集または印刷用コンピューターにインストールすることをお勧めします。

フォントがインストールされていない場合、PowerPoint によってフォントが置き換えられ、改行やレイアウトの変更が発生する可能性があります。

## KataGo 解析

![KataGo 分析](../gotepad-gd/assets/ui/katago.svg)

Gotepad のデスクトップ バージョンでは、KataGo 実行可能ファイルとニューラル ネットワーク モデルがソフトウェアとともに配布されません。使用する前に設定で次のことを指定する必要があります。

1. KataGo 分析エンジンの実行可能ファイル。
2. このバージョンと互換性のあるニューラル ネットワーク モデル (通常は `.bin.gz`);
3. 分析エンジンによって使用される「.cfg」構成ファイル。

設定が完了したら、「パスのテスト」をクリックします。「自動パフォーマンス検出」を実行して、プログラムに検索スレッド数とバッチサイズを推定させることもできます。TensorRT などのバックエンドは初回の初期化に時間がかかる場合があり、検出には固定の制限時間を設けていません。現在のウィンドウの約 80% を占めるモーダルウィンドウで、自動的に折り返されるリアルタイム出力を確認し、手動で停止できます。検出に成功したら、結果ウィンドウで「適用」をクリックすると、構成が書き込まれて設定が有効になります。「キャンセル」をクリックするか結果ウィンドウを閉じる場合は、誤操作による再検出を防ぐため、先に確認が表示されます。検出中は他の設定が一時的に操作できなくなります。

### 現在局面を解析

KataGo パネルを開いた後:

- 再生ボタンをクリックすると、現在の 局面分析が開始され、設定された更新間隔に従って結果が更新されます。
- 一時停止ボタンはインターフェイスの更新を一時停止するだけで、KataGo は計算を続けます。再開すると、最新の結果が表示されます。
- [停止] ボタンは、現在の分析を終了するリクエストをエンジンに送信します。
- 「解析量を増やす」は右側の入力欄の `maxplayouts` で現在局面を再解析します。正の値が必要です。上下矢印の増減幅は保存済みの「解析量」と同じで、この設定を保存すると更新されます。整数を手入力することもできます。解析中も画面更新の一時停止や解析の停止が可能です。
- 「継続分析」を有効にすると、新しい局面へ移動したときに自動的に再分析されます。このとき、再生、一時停止、停止ボタンは継続モードによって制御されます。棋譜タブを切り替えたり、現在の棋譜を閉じたりすると継続分析は自動的に停止し、切り替え後の棋譜でそのまま実行されることはありません。

Android 版では、現在局面の解析、継続解析、再生経路全体の解析について、結果の進行状況を監視します。アプリがバックグラウンドにある間は監視を一時停止し、フォアグラウンドに戻ると計時を再開します。KataGo から長時間結果が返らない場合は、OpenCL 解析サービスを自動的に再起動し、未完了の要求を復元します。自動復旧後も応答がない場合は、その解析を停止して再実行を案内します。

候補テーブルには、位置、現在の手番側の勝率、目差、変化図への入口が表示されます。上位 3 候補は半透明の濃い緑、明るい緑、黄色で碁盤上に表示され、「盤面の追加候補数」でさらに 0 ～ 99 個を明るい黄色で表示できます。「上位3候補の不透明度」と「その他の候補の不透明度」で、2 種類の盤面マーカーの不透明度を個別に調整できます。「目数差を表示」を有効にすると、次の行にある「盤面候補に目数差を表示」も選択できます。有効にした場合、各候補マーカーの上部に現在の手番側の勝率、下部に目数差が表示され、中央は横線で区切られます。「目数差を表示」を無効にすると、「盤面候補に目数差を表示」も同時に無効化され、選択できなくなります。候補位置が現在の棋譜経路上の実際の次の一手と一致すると、追加候補を含めて細い黒枠が付きます。棋譜経路全体を解析済みで、実際の次の一手が上位 3 候補に含まれず、その着手後の勝率が第 1 候補より 10 ポイント以上低い場合、実際の着手位置に淡い赤の円で勝率差を負数表示します。表の「入る」を押すと候補手順を変化図に読み込みます。碁盤がロック中なら、盤上の候補マーカーを直接押して対応する変化図に入り、保持するか破棄するかを選べます。

### 再生経路全体を解析

「再生経路全体を解析」を押すと、「全局高速解析量」で各局面の勝率・目差曲線を作成します。現在の経路だけを対象とし、他の分岐は解析しません。実行中は「全局解析をキャンセル」に変わり、もう一度押すと停止します。受信済みの結果は残ります。初期計算量は傾向を素早く見るため低く設定されており、精密な判断には向きません。縦線は現在局面を示し、曲線上の他の位置を押すと移動できます。KataGo パネルを閉じると現在局面と全体の解析を停止し、継続解析も解除します。

KataGo の勝率と目差は、ルール、コミ、モデル、計算量、ハードウェアの影響を受けます。訪問数が少ないと結果が大きく変動するため、重要な結論は計算量を増やして確認してください。デスクトップ版はユーザーが設定した外部 KataGo エンジンを使用します。Android 版はデバイスの OpenCL GPU バックエンドを優先し、OpenCL が利用できない場合や起動に失敗した場合は、互換性の高い Eigen CPU バックエンドへ自動的に切り替えます。iOS 版は内蔵の KataGo Metal GPU バックエンドと 10b モデルを使用し、実行ファイルの指定は不要です。バックグラウンドに移ると解析は停止し、前面に戻ってから再開できます。Android と iOS の終局の数え上げは、通常の解析で選択した外部モデルや Human SL モデルを使用せず、内蔵 10b モデルと専用設定を使用します。「数え上げの計算量」は引き続き有効です。数え上げを開始すると他の解析エンジンを解放し、終了後に再び解析する際は元の選択モデルを読み込み直します。数え上げ中にバックグラウンドに移ると数え上げモードを終了します。iOS 版でも外部モデルのインポートと、通常の解析または Human SL の自動パフォーマンス検出が可能です。検出後に「適用」を押すと、推奨スレッド数とバッチサイズを保存できます。検出中はアプリを前面に保ってください。バックグラウンドに移ると検出は中止されます。

## 人間らしい対局

![人間らしい対局](../gotepad-gd/assets/ui/katago_human_play.svg)

通常の KataGo アイコンの下にある 人間らしい対局 アイコンをクリックして、現在の盤面から Human SL モデル 対局を開始します。開始する前に、AI が黒でプレイするか白でプレイするか、現代または AlphaGo 棋風 をプレイするか、シミュレートする 棋力、およびハンドごとの AI 計算量を選択できます。計算量入力ボックスには、「人間模倣対局の計算量」設定の現在の訪問値が表示され、ダイアログ ボックスの一時的な調整は、この 対局に対してのみ有効になります。値が低いほど高速ですが、マスター モデルを評価する人間の候補が少なくなり、重大な間違いが発生する可能性が高くなります。値を大きくすると、選択された人間を保持しながら、過剰な損失を伴う候補者が完全に抑制されます。現代棋風と AlphaGo 以前の棋風の 9d では、明らかな悪手を抑えるためにメインモデルの評価をより強く反映し、その他の棋力では従来の着手選択方式を維持します。プログラムは現在の盤面を保持するため、すでに 棋譜がある中央の 局面を AI に引き継いで引き継ぐことができます。

人間模倣対局モードに入ると、KataGo 分析パネルが自動的に開きます。人間模倣対局は一時的な 棋譜を使用し、プログレス バーと通常の 碁盤ツールは一時的に非表示になり、KataGo 分析、終局の地合い計算、一手戻す、キープ ボタンとギブアップ ボタンのみが保持されます。現在の 局面操作、候補テーブル、および分析パネルの右下隅にある 棋譜全体の簡易解析 ボタンはすべて操作できませんが、勝率 および 目差 曲線は 対局の結果で更新され続けます。人間模倣対局中は、マウスホイール、矢印キー、再生バー、進む・戻るボタン、解析曲線による棋譜の移動はできません。人間の手番では、専用の「一手戻す」ボタンでのみ、直前の人間の着手とそれに続く AI の応手をまとめて取り消せます。AI の思考中は手を戻せません。モードを終了すると、分析パネルはモードに入る前の開いた状態または閉じた状態に戻ります。対局中に棋譜タブを切り替えるか新しい棋譜を作成すると、現在の対局を保存して続行するか、破棄して続行するか、操作を取り消すかを確認します。AI が思考中の場合は確認中に探索を一時停止し、操作を取り消すと再開します。

分析パネルのステータス メッセージには、現在の Human SL ギアが接頭辞として付けられます (例: 「[rank_1d] AI は考えています...」)。 「rank_」は現代の 棋風 を表し、「preaz_」は AlphaGo が登場する前の 棋風 を表し、後半はこのゲームで選択された 棋力 を表します。

AI がパスを選択すると、プログラムはユーザーにもパスするかを確認します。独立したパスボタンはありません。「着手を続ける」を選択した場合は、そのまま盤上で対局を続けられます。双方がパスした後は、終局計算で結果を確認できます。設定で「AI の投了提案」を有効にすると、連続する勝敗評価と現在の目数差を組み合わせて、黒白の双方について判定します。最低手数に達する前から連続評価は蓄積されますが、早期に通知されることはありません。内部の投了条件を満たしても通知を表示するだけで、いずれかの側を自動的に投了させたり、対局を終了したりすることはありません。続行、保存、破棄はユーザーが選択できます。通知するたびに黒白双方の連続判定記録を消去し、最初から蓄積し直します。緑色の `✓` をクリックすると、現在の対局を終了して手順を元の棋譜に記録するか確認され、承認後に実行されます。赤色の `✕` または `Esc` は、確認後に今回の対局記録を破棄します。

## 終局の地合い計算

![終局の地合い計算](../gotepad-gd/assets/ui/territory_scoring.svg)

終局の地合い計算は現在、中国ルールのみに対応しています。使用前にすべてのダメを詰め、碁盤右側のツールバー末尾にある終局の地合い計算アイコンをクリックしてください。地合い計算中は石の上の手数を一時的に非表示にし、終了すると元の表示設定に戻ります。設定の「終局計算量」に従って KataGo が各交点の黒白の所有を判定します。この計算量はデフォルトで 200 visits であり、通常の解析量や人間模倣対局の計算量とは独立しています。判定結果は半透明の領域マーカーで碁盤上に表示されます。緑色の `✓` と赤色の `✕` の横にある独立したログパネルには、エンジンの起動情報と判定の進行状況がリアルタイムで 1 行ずつ表示されます。

KataGo の死活・所属判定には誤りがあり得ます。交点を押すと、上下左右につながる同じ所属の領域全体を反対側へ切り替えます。確認後に緑の `✓` を押すと、計算用の盤面から死石と判定した石を除き、残った空点の領域を判定して、黒白の石数、空点数、コミ、中立点、勝敗と目差を表示します。白の合計にはコミを含みます。計算モードを終了して結果を表示するだけで、元の棋譜から石を削除したり棋譜の結果を自動入力したりはしません。赤の `✕` または `Esc` でも棋譜を変更せず終了します。あくまで確認の補助として使い、複雑な死活、セキ、未処理のダメはご自身で確認してください。

## 設定

右上の歯車ボタンをクリックするか、`Ctrl+O` を押します。設定を変更した後は、パネル左上の緑色の `✓` で保存、青色の `↺` で今回の変更を元に戻し、赤色の `✕` でキャンセルして閉じます。左側の `∧`、`∨` ボタンを使って、設定の表示領域の高さの 3 分の 2 ずつ滑らかに上下へスクロールできます。

### インターフェース言語

「インターフェース言語」では、中国語、日本語、韓国語、英語を選択できます。切り替えると選択言語がすぐにプレビューされ、緑色の `✓` で保存すると次回起動時にも使用されます。青色の `↺`、赤色の `✕`、またはパネルを閉じる操作では、設定を開いた時点の言語に戻ります。ボタン、メッセージ、ツールチップ、および `[GNE…]` 番号付きのコア命令メッセージは選択言語に切り替わりますが、棋譜タイトル、ノート、ファイル名、KataGo の生ログ、SGF 自体の内容は翻訳されません。デスクトップのネイティブ ファイル選択画面では、タイトル、確認ボタン、ファイル種類の説明は Gotepad の現在の表示言語を使用し、それ以外のシステム提供文字列は OS の言語のままになる場合があります。

### 外観と再生

- 碁盤テクスチャ: 明るい木目または暗い木目を切り替えます。
- 石テクスチャ: 光沢またはマットな白黒 石を切り替えます。
- 画面の左右のマージン (モバイルの場合): ピクセル単位で、碁盤、タブ バー、ボタン、パネルを画面の左端と右端から同時に離し、対称に適用します。デフォルトは「0 px」です。丸い角や切り欠きのある横長のデバイスでは、コントロールが完全に表示されるまでこの値を徐々に増やすことができます。背景テクスチャは引き続き画面全体に表示されます。
- 碁盤水平幅比率: 元の利用可能な水平スペースの最大比率を使用するように 碁盤を制限します。許容範囲は「50%~100%」で、デフォルトは「100%」です。 「4:3」などの水平方向のスペースが狭い画面では、適切に調整してメモや KataGo 分析パネル用にさらに多くのスペースを確保できます。 碁盤は端が切れることなく完全に表示されます。
- UIの拡大縮小：有効にすると、ウィンドウの高さに応じて線形に計算される UI 倍率に、右側で指定した倍率を掛けます。初期値は `1.5` 倍で、スマートフォンやタブレットでのタッチ操作に便利です。設定範囲は `0.50～2.00` です。増減ボタンは一回につき `0.1` ずつ変更し、手入力は小数点以下二桁に対応します。範囲外の値は反映されません。デスクトップ版でも使用できます。
- 着手番号表示：直近 1 手、10 手、全手、指定手数から選択できます。初期設定は直近 1 手で、指定範囲は 1～9999 手、指定値の初期値は 20 です。
- 絶対 手数: 現在の分岐からの絶対 着手手数 を使用します。それ以外の場合は、相対番号を表示します。
- 再生間隔：自動再生の各手の待ち時間。0.1～60 秒、初期値は 1 秒です。
- 着手サウンド効果: 0 ～ 100 のスライダーを使用して調整します。デフォルトは 50 で、0 に設定するとミュートになります。プログラムは 5 つの実際の 囲碁着手 録音をランダムに再生します。新しい 着手が正常に作成され、次の 着手ノードにローミングされると再生されます。 棋譜をロードしても、プリセット ノードおよび 置き石 へのローミングはトリガーされません。
- 着手確認: 最初に半透明の未確定の石を表示し、緑色の `✓` アイコン、または同じ位置の再クリックで着手を確定できます。デスクトップではデフォルトでオフ、モバイル端末ではデフォルトでオンになっています。
- PPTX 碁盤画像: SVG と PNG を切り替えます。デフォルトは SVG です。
- 碁盤座標をエクスポート: PPTX 碁盤の上側に列文字を表示し、左側に行番号を表示します。デフォルトはオフです。

### KataGo

- 解析計算量：現在局面の `maxVisits`。1～100000、初期値は 5000 です。
- 地合い計算量：終局の所属判定の `maxVisits`。1～100000、初期値は 200 で、通常の解析計算量とは独立しています。
- 解析更新間隔：途中結果を受信する間隔。0.1～60 秒、初期値は 1 秒です。
- 候補変化図の手数：候補 PV の表示と変化図への入力の最大手数。1～1000、初期値は 10 です。
- 追加ボード候補数: 上位 3 候補に加えて表示されるボード候補の数。範囲は 0 ～ 99 で、デフォルト値は 0 です。
- 上位3候補の不透明度: 上位 3 候補の盤面マーカーの不透明度です。範囲は 0% ～ 100%、デフォルトは 70% で、矢印を押すたびに 10% ずつ変化します。
- その他の候補の不透明度: 追加候補の盤面マーカーの不透明度です。範囲は 0% ～ 100%、デフォルトは 30% で、矢印を押すたびに 10% ずつ変化します。
- 目差 を表示: 候補テーブルと曲線に 目差 を表示するかどうかを制御します。
- 盤面候補の目差表示：「目差表示」が有効なときに選べ、初期状態は無効です。候補マークに勝率と目差を表示します。「目差表示」を無効にするとこちらも無効になります。
- 棋譜全体の高速解析計算量：各局面の visits。1～100000、初期値は速度優先の 1 です。
- テスト パス: 実行可能ファイル、モデル、構成が起動できるかどうかを確認します。
- 自動パフォーマンス検出: KataGo が検出を完了するか、ユーザーが停止するまで実行を続け、現在のデバイスに適したパラメーターを推定します。実行中はベンチマーク出力がモーダルウィンドウに表示され、完了後はそのウィンドウで結果を直接適用するか、再確認を経てキャンセルできます。

解析設定を保存しても、既存の候補結果、勝率曲線、目差曲線は保持されます。実行中の古い解析リクエストは停止されますが、継続解析が有効だった場合は、新しい設定で自動的に再開します。棋譜全体の簡易解析は自動的には再実行されません。再度実行すると、新しい結果が既存の曲線を順次置き換えます。KataGo の実行ファイル、モデル、または設定を変更した場合、置き換えられるまで保持される結果は変更前のエンジン設定によるものです。

自動性能検出の結果画面の「適用」は、設定パネルの他の未保存変更も同時に保存します。適用前にまとめて確認してください。人間らしい対局の計算量は 1～100000 visits、初期値は 200 です。

設定を開くときに、保存された KataGo パスが無効になると、インターフェイスはパスをクリアし、再度パスを選択するように要求します。自動的に生成されたパフォーマンス設定は Godot のユーザー データ ディレクトリに保存され、Windows、Linux、macOS での権限の違いに対応するためにインストール ディレクトリには書き込まれません。

「KataGo 人間らしい対局」は独立した設定領域です。デスクトップ版では、使用する KataGo 実行ファイルに対応した Human SL `.bin.gz` モデルを選択してください。Android と iOS ではシステムのファイル選択画面からモデルをインポートし、アプリがインポート後のファイルを管理します。Human SL モデルを通常の解析モデルで代用することはできません。通常の解析と人間模倣対局ではモデルの用途が異なります。モバイル版はインポート時とエンジン起動時にモデル内部の種類を確認し、用途が違う場合はメッセージを表示します。ファイル名で用途が決まるわけではありません。Android と iOS の人間模倣対局は、通常の解析で外部モデルを選択していても、メイン解析モデルとして内蔵 10b を使用します。デスクトップ版は選択したメイン解析モデルを引き続き使用します。「人間模倣対局の計算量」は新しい対局の初期訪問数と自動パフォーマンス検出の実際の負荷の両方に使われるため、変更後はこの領域で検出をやり直してください。「AI の投了提案」は初期状態では無効で、有効にしても対局中の投了通知を追加するだけです。棋局を自動操作することはありません。検出は人間模倣対局専用の設定を生成し、通常の解析モデルの検出結果は直接再利用しません。

人間模倣対局のパフォーマンステストを開始すると、まず設定パネルのモデルパスが確認されます。パスがまだ保存されていないか、現在有効なパスと異なる場合は、先にパスを保存して続行するかどうかを確認します。その後、ファイルが実際に存在すること、読み取り可能であること、対応形式であることも確認されます。確認に失敗した場合は、有効なモデルを選び直す必要があります。パフォーマンステストに成功したら、結果ウィンドウの「適用」をクリックすると、新しく生成されたパフォーマンス構成が書き込まれて有効になります。結果をキャンセルする前には、もう一度確認が表示されます。

Android と iOS で通常解析モデルまたは Human SL モデルを取り込む場合、ファイルサイズは 1 KB～1 GB で、モデルサイズの 2 倍以上の空き容量が必要です。取り込み後に設定を保存してください。設定を取り消すと今回取り込んだモデルは有効になりません。

## Android と iOS 版

Android の現在のバージョンは、Android 9 以降を搭載した arm64-v8a デバイスをサポートしており、横向きでの使用向けに設計されています。 APK ファイルをデバイスにコピーしてインストールします。システムがインストールをブロックした場合は、システムのプロンプトに従って、そのソースからアプリケーションをインストールできるようにする必要があります。

Android と iOS の設定パネル、人間模倣対局の開始ダイアログ、KataGo 分析パネルでは、数値欄を軽くタップしてもキーボードは表示されません。数値部分を 0.5 秒間長押しするとキーボード入力が開始されます。ノートのタイトル、ノート本文、棋局情報パネル内のテキスト欄も同じ長押し方式を使用するため、軽いタップやドラッグではキーボードがすぐに表示されません。右側の数値調整ボタンは幅を広げ、矢印も大きくしてタッチしやすくしていますが、元の行の高さは変更していません。

Android バージョンには、KataGo OpenCL/Eigen 分析バックエンド、モデル、および内部管理される構成ファイルが組み込まれており、実行可能ファイルや構成パスを選択する必要はありません。現在 APK に組み込まれているモデルは「g170e-b10c128-s1141046784-d204142634」で、KataGo g170 拡張トレーニングの 10 ブロック / 128 チャネル ネットワークに属しています。 Jane Street と KataGo の著者である David J. Wu (lightvector) の g170 トレーニング バッチへのコンピューティング能力とデータの提供、および CC0 に基づくパブリック ドメインへの関連モデル データの提供に感謝します。モデルのダウンロード画像を提供してくださったパチプロジェクトにも感謝します。設定の「ニューラル ネットワーク モデル」はデフォルトで組み込みモデルを使用します。 「参照」をクリックして、Android システムのファイル セレクターを介して標準の KataGo `.bin.gz` または `.txt.gz` ウェイトをインポートすることもできます。インポート プロセスではモデルが Gotepad のアプリケーション データ ディレクトリにコピーされるため、その後の元のファイルの移動や削除は使用には影響しません。大きなモデルをインポートする前に、デバイスに十分なストレージ容量と実行メモリがあることを確認してください。 BadukAI などのソフトウェアで使用されるデュアルファイル Android 最適化モデルは標準の KataGo ウェイトではないため、ここで直接ロードすることはできません。 「内蔵」をクリックし、緑色の「✓」で保存すると、ソフトウェア付属のモデルに戻ります。プログラムは、デバイスによって公開される OpenCL GPU バックエンドの使用を優先します。デバイスに利用可能な OpenCL 実装がない場合、ドライバーの初期化が失敗する場合、または独立した分析プロセスが異常終了した場合は、自動的に Eigen CPU バックエンドにフォールバックします。分析計算量、リフレッシュ間隔、候補 変化図手数、目差 表示、棋譜全体の簡易解析 計算量などのオプションは引き続き調整でき、自動パフォーマンス検出も実行できます。検出が完了したら、結果ウィンドウの「適用」をクリックすると、結果が内部構成に書き込まれます。 OpenCL バックエンドは、初めて実行するとき、またはモデルを変更するときに現在の GPU に合わせて調整する必要があるため、その後の起動よりも大幅に遅くなる可能性があります。分析により消費電力と発熱が増加します。長時間分析する場合はデバイスの温度に注意することをお勧めします。

Android 版の設定には「特定モデルの高速化」があり、初期状態では無効です。構造に互換性があるモデルによる 19×19 の解析が対象です。主幹全体、入れ子の残差ブロック、Attention、FFN、出力ヘッドをたどり、実際の構造と演算の寸法で最適化処理を選択します。ファイル名、内部名、学習チェックポイントには依存しません。有効にしたら緑色の `✓` で保存してから、自動パフォーマンス検出または通常の解析を実行してください。無効にして保存すると元の実装に戻ります。モデル、盤面サイズ、計算条件が対応条件を満たさない場合は元の実装を使用します。チップや GPU の型番による制限はありません。実験的な機能のため、実際に速くなるかは端末での測定が必要です。無効時と有効時にそれぞれ自動パフォーマンス検出を行い、同じ局面の解析結果に不自然な変化がないかも確認してください。検出ウィンドウには今回使用する保存済みの設定が表示されるため、チェックを入れるだけでなく保存が必要です。モデルの読み込み後、測定開始前には、モデル内部名、構造の適合状況、候補カーネル数、バックエンドでの実際の有効状態も表示されます。初期化の失敗や実行中に元の実装へ戻った場合も通知されます。項目の右側にある `?` ボタンで、対応モデル、検証状況、比較方法を確認できます。初期の開発とテストは玄戒 O3（XRing O3）で行っており、他の GPU での効果は保証されません。同じ端末でこの機能を無効・有効にし、その都度保存してから自動パフォーマンス検出を実行し、結果を比較してください。新しい端末では数値検証も推奨します。

初期の実装では、tf2-b10c384 と b18c384nbt について玄戒 O3（XRing O3）で高速化と数値比較を行いました。新版は、形式バージョン 14～17、メタデータ入力なし、互換演算を含む畳み込み、NBT、Transformer および混合ネットワークを構造で判定し、学習チェックポイント、ブロック数、チャネル幅を固定しません。行列の入力チャネル数は 16 の倍数、出力チャネル数は 32 の倍数、バッチサイズは 1～32 が条件です。配置条件を満たす 1×1 畳み込みと射影を高速化でき、QKV と SwiGLU の融合には寸法の一致も必要です。他の演算は元の実装を使用します。構造の適合は、全演算の置換や数値・性能検証の合格を意味しません。新版では置換される演算が増える可能性があるため、以前にテストしたモデルも再検証してください。

「特定モデルの高速化」では、互換性のある NBT モデルの末端の射影と残差加算を一つの処理にまとめ、中間データの読み書きと個別の演算を減らす最適化も利用できるようになりました。この設定を有効にして保存すると、条件を満たすモデルに自動で適用され、追加の設定は不要です。条件を満たさない部分は元の実装を使用します。効果は端末、モデル、スレッド数、バッチサイズによって変わるため、構造が適合するだけで高速化を判断することはできません。更新後は数値検証を再度行い、性能診断を無効にして同じ局面で速度を比較することを推奨します。

特定モデルの高速化には、バックエンドで FP16 ストレージが有効になっている必要があります。実験用カーネルは端末の FP16 対応状況を独立して確認してコンパイルを試みるため、元のバックエンドでも FP16 計算が選択されている必要はなくなりました。自動チューニングで FP16 計算が選ばれなかった場合でも、端末が FP16 に対応していないことや、実験用カーネルが必ず遅いことを意味しません。パフォーマンス検出では、FP16 ストレージが無効、端末の能力が要件を満たさない、カーネルのコンパイルに失敗した、といった原因を区別して表示します。実験経路と元の実装では計算精度が異なる場合があるため、新しい端末では速度を比較する前に数値検証を行ってください。

Android 版には「数値検証」ボタンもあります。構造に互換性がある解析モデルを選択して保存し、このボタンを押してください。現在の解析を一時停止し、固定の手順で生成した 32 個の合法局面を用いて、バッチサイズ 1、2、4、8、16、32 で元の実装と実験的な実装を自動比較します。繰り返し実行時の再現性と、単独評価とバッチ評価の一致も確認します。検証中は性能診断を自動的に無効にし、二つの実装を自動で切り替えます。高速化を手動で切り替える必要はなく、保存済みのスレッド数、バッチサイズ、スイッチ設定も変更しません。ウィンドウには着手確率、勝率、目差、領地の帰属予測の最大差と、レポートの保存先が表示されます。勝率と着手確率は 0～1、目差は目単位です。「停止」で検証を中断できますが、未完了のレポートは検証合格の根拠にはなりません。「完了、レポートは確認待ち」はデータ収集の完了だけを意味し、数値の正しさが確認されたことを意味しません。また、生成局面だけでは実際の棋譜におけるコウ争いや死活などの個別検証を代替できません。

「性能診断（速度に影響）」は独立した設定で、初期状態では無効です。性能上の問題を調べるために情報を収集する場合は、有効にして緑色の `✓` で保存し、解析モードに入ってください。同じ局面を少なくとも 1 分間解析し、必要に応じて解析の計算量を増やしてください。診断には追加の処理負荷がかかるため、有効時に表示される速度を通常の性能として扱うことはできません。収集後は無効にして保存してください。自動パフォーマンス検出では常にこの診断を無効にしますが、保存済みの高速化設定は使用します。Android では、各回のパフォーマンス検出レポートと診断ログを個別に保存するため、後から取得して調べられます。二つのモデルや高速化の有効・無効を比較する際は、同じ棋譜局面を使用し、端末の温度、電源供給、画面の状態をできるだけ揃えてください。

Android のパフォーマンス検出、性能診断、数値検証の履歴ログは、従来のアプリ固有外部ファイルディレクトリ内にある `o3-profile` フォルダーへ保存されます。プログラムは起動後および実行中に履歴を確認し、バックエンドが終了してログへの書き込みが止まった後、古いものから順に整理します。保持目標は最大 20 グループ、合計 200 MiB 以下です。1 回の数値検証で生成された各バッチのレポートと集計は 1 グループとして扱い、グループ情報のない旧バージョンの検証レポートはまとめて保持または削除します。実行中の処理は削除されず、最新の 1 グループも保持されるため、容量が一時的に上限を超える場合があります。1 つの性能診断ファイルが約 20 MiB に達すると、打ち切りマーカーを記録して以後のサンプリングを停止しますが、棋局の解析は継続します。新たに収集する必要がある場合は、解析を停止してから再開してください。長期間保存するレポートや不具合調査のために提出するレポートは、早めに別の場所へコピーしてください。これらの履歴ログは、システムの「キャッシュを削除」機能では整理されません。

Android バージョンでは、システム ファイル セレクターを通じて SGF をロードすることも、システム クリップボードから完全な SGF テキストを貼り付けることもできます。中国語、日本語、韓国語などのファイル名と 棋譜の内容は正常に表示されます。

iOS 版では、新規作成画面の「読み込み」を押すとシステムのファイル選択画面が開き、「ファイル」内の本体ストレージ、iCloud Drive、または有効な他のファイルプロバイダから `.sgf` を選択できます。「ファイル」や「このアプリで開く／共有」に対応した他のアプリから、Gotepad を選んで SGF を開くこともできます。Gotepad が起動していない場合は起動して読み込み、起動済みの場合は新しいタブで開きます。iOS では元のファイル名を保持したコピーをインポートするため、編集しても元ファイルを直接上書きしません。初回の保存と「名前を付けて保存」では、システムのファイル画面で保存先を選択します。保存に成功すると、以後の「保存」は選択したファイルを更新します。ファイルが移動された場合、アクセス権が無効になった場合、またはファイルプロバイダが書き込みできない場合は、「名前を付けて保存」で保存先を選び直してください。PPTX のエクスポートでは、教材を生成してからシステムのファイル画面で保存先を選択します。選択を取り消すと教材は保存されません。iOS の新規作成画面で「画像」を押すと、「写真」または「ファイル」を選択できます。「写真」では写真やスクリーンショットを選択でき、「ファイル」では本体ストレージ、iCloud Drive、他のファイルプロバイダの画像を選択できます。写真の選択では選んだ画像のみを読み込むため、写真ライブラリ全体へのアクセス許可は不要です。選択を取り消すと新規作成画面に戻ります。iOS でも碁盤画像の自動認識と四隅・石の校正に対応しています。「撮影」を初めて使用するとカメラへのアクセス許可を求めます。以前に拒否した場合は、システム設定で Gotepad のカメラ使用を許可してください。撮影した画像は碁盤のインポートにのみ使用され、システムの写真ライブラリには自動保存されません。

システム「で開く」をサポートする Android ファイル マネージャーまたはその他のアプリケーションは、Gotepad を使用して SGF を直接開くことができます。アプリケーションが実行されていない場合は、起動して 棋譜がロードされます。アプリケーションがすでに実行されている場合は、新しいタブで開きます。すでに開いている同じ 棋譜が既存のタブに切り替わります。外部アプリケーションによって提供されるファイルには、読み取り権限のみが与えられる場合があります。この場合、ツールバーの「保存」は自動的に変更され、新しい保存場所が選択され、読み取り専用ソースは上書きされません。

Android で SGF を保存または別名保存するときは、ファイル選択と保存確認を完了してからアプリを閉じてください。保存成功のダイアログはありません。PPTX は成功または失敗の表示まで待ってください。元ファイルを上書きできない場合は「名前を付けて保存」で別の保存先を選んでください。

Android 版は PNG 互換モードでの PPTX エクスポートに対応しています。使用するプレゼンテーションソフトで SVG の碁盤画像を表示できない場合は、設定で PNG に切り替えてください。SVG 画像を含む PPTX は Microsoft 公式の PowerPoint アプリで閲覧・編集できますが、WPS では SVG 画像が表示されない場合があります。

## データの保存場所と利用上の注意

- 設定と KataGo 自動パフォーマンス構成は、現在のシステム ユーザーのアプリケーション データ ディレクトリに保存されます。
- SGF と PPTX はユーザー自身の選択で保存され、`user://` には自動的には保存されません。
- 現在のバージョンには、完全な未保存ステータス プロンプトと自動回復メカニズムがありません。タブまたはプログラムを閉じる前に、積極的に保存する必要があります。
- 枝を一括でカットしたり、棋譜の情報を編集したり、大量のノートを調整したりする前に、まずバックアップファイルとして「保存」することをお勧めします。
- ソフトウェア間の交換が必要な場合は、他のソフトウェアがカスタム属性を破棄しないように、Gotepad の元の SGF のコピーを保持することを優先します。
- 印刷またはコースウェアの配信に使用する場合、フォント、碁盤 画像、およびページング効果をターゲット コンピューターで確認する必要があります。互換性が不明な場合は、デスクトップ バージョンを PNG を使用してエクスポートできます。
- KataGo 分析は引き続き CPU/GPU を使用します。ノート編集などの軽い操作中は解析を停止して、消費電力とデバイス温度を削減できます。
